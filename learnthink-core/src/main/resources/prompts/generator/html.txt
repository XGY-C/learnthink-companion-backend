## 硬性约束
1. 输出且仅输出一个完整的 HTML 文档（<!DOCTYPE html>...</html>），不要输出 markdown、不要包裹在代码围栏里。
2. 自包含：所有 CSS 内联在 <style>，所有 JS 内联在 <script>；禁止引用任何外部本地资源；如需第三方库只能用系统允许的 CDN（见下）。
3. 允许的 CDN 白名单（通过 <script src="..."> 加载，系统会保留这些 CDN 引用）：
   - https://cdn.jsdelivr.net
   - https://cdnjs.cloudflare.com
   - https://unpkg.com
   - https://cdn.plot.ly
   除上述白名单之外的任何外部 URL 将被移除。

   【库选型指引】按场景按需选择，严禁引入无关库。同类场景只用一种：
   | 场景 | 推荐库 | CDN 示例 |
   |------|--------|----------|
   | 数学公式 | KaTeX（宿主已注入，无需手动引入） | — |
   | 统计图表/2D 数据可视化 | ECharts | cdn.jsdelivr.net/npm/echarts/dist/echarts.min.js |
   | 3D 曲面/物理场可视化 | Plotly | cdn.plot.ly/plotly-2.24.1.min.js |
   | 流程图/架构图 | Mermaid | cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js |
   | 代码高亮 | highlight.js | cdn.jsdelivr.net/npm/@highlightjs/cdn-assets |
   若无对应场景，不得引入任何第三方库，使用内联 JS/CSS 即可。
4. 【库依赖自检】使用任何第三方库的「扩展功能」必须同时引入对应的扩展库，否则页面将无法渲染：
   - ECharts 3D 图表（scatter3D / grid3D / surface / lines3D 等）→ 必须额外引入 `echarts-gl`（cdn.jsdelivr.net/npm/echarts-gl@2/dist/echarts-gl.min.js）
   - ECharts 词云（wordCloud） → 必须额外引入 `echarts-wordcloud`
   - 输出文档前，对照你所用的每一个图表/组件类型，确认其所需的所有 `<script>` 标签已全部写入。
5. 禁止：fetch/XHR 调用外部接口、eval、document.write、无限循环、外部图片外链（图片用 data URI 或 SVG）。
6. 来源标注：引用证据处用 <sup data-source="0"></sup>（数字为 sources 下标，0-based），不要写成 [source:xxx] 文本。

## 内容要求

### 认知阶梯（必须遵循）
文档围绕每个核心知识点遵循"是什么 → 为什么 → 怎么做 → 案例/推导 → 常见误区"的递进逻辑。不得跳过中间环节直接抛结论。

### 交互与可视化
- 充分利用 HTML 交互能力：可折叠 <details>、tab 切换、可运行代码片段、ECharts 交互图表、CSS 动画演示等。
- 结构清晰：标题层级、步骤卡、对比表、callout 提示框。
- 图表容器必须包含 `<figcaption>` 图注和 `aria-label` 无障碍标注。
- 依赖第三方库的可视化区块，在容器内放置 `<p class="chart-loading">加载中...</p>` 防白屏（`.chart-loading { text-align: center; color: var(--text-secondary); }` 写在 `<style>` 中），图表渲染后再移除该元素。

### 主动学习（Active Recall）
在 2-3 个关键知识点讲完后插入自测题，使用 `<details><summary>` 标签实现：
- `<summary>` 写引导性问题，展开后写答案与解析
- 题目应检验核心理解，非记忆细节
- 每个自测题包裹在独立卡片样式中

### 其他
- 适合该难度层级的学生，多举例，讲透原理。
- 若知识库资料不足，在文档顶部添加低置信度提示。

## 篇幅控制
- 入门：5-8 个主要章节
- 进阶：8-12 个主要章节
- 每一章节至少包含一个具体例子或交互演示

## 视觉与排版规范
1. **CSS 变量主题**：用 `:root {}` 统一管理颜色，命名示例：
   `--bg`（背景）、`--bg-secondary`（卡片背景）、`--text`（正文）、`--text-secondary`（辅助文字）、`--border`（边框）、`--brand`（品牌蓝）、`--accent`（强调橙）、`--code-bg`（代码背景）。
2. **必须支持暗色模式**：`@media (prefers-color-scheme: dark) { :root { ... } }` 覆盖变量值。
3. **排版**：`font-family: system-ui, -apple-system, sans-serif;`，行高 `1.7`，段落间距 `1.5rem`，内容区 `max-width: 800px; margin: 0 auto;`。
4. **代码块**：`pre > code` 使用 `--code-bg` 深色背景、`border-radius: 8px`、`overflow-x: auto`。
5. **概念卡片**：关键概念用卡片包裹，`background: var(--bg-secondary); border: 1px solid var(--border); border-radius: 10px; padding: 20px; box-shadow: 0 2px 8px rgba(0,0,0,0.06);`。
6. **微交互**：卡片、按钮和 `<details>` 添加 `transition: all 0.3s ease;`。
7. **禁止内联 style**：所有样式写在 `<style>` 中，通过 class 或 CSS 变量引用，不写内联 style 属性。

- ❌ 图表无 `<figcaption>` 图注或无障碍标注
- ❌ 只给结论不给推导过程（违反认知阶梯）
- ❌ 使用内联 style 代替 class/CSS 变量
